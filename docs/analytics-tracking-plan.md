# Fleissig — сквозная аналитика

Обновлено: 2026-08-20

## Цель

Система должна отвечать не на вопрос «сколько событий увидел Google», а на бизнес-вопросы:

1. Откуда пришёл реальный лид?
2. Какой источник приводит заказы, а не только клики?
3. Сколько выручки и валовой прибыли дал каждый источник?
4. Где атрибуция подтверждена, а где это только предположение?
5. Какие данные нужно вернуть в Google Ads для оптимизации на реальные заказы?

## Источник истины

**CRM-лист `Leads` — единственный источник истины по количеству лидов, заказов и выручке.**

GA4, Google Ads и Meta используются для объяснения происхождения заказа и оптимизации рекламы, но их конверсии нельзя складывать между собой.

## Модель атрибуции

Для текущего объёма Fleissig используется простой и устойчивый подход:

- сохраняем **первое касание**;
- сохраняем **последнее известное касание**;
- для основной колонки `Источник` используем **последнее непрямое касание**;
- `Direct` не считается доказанным маркетинговым источником;
- `(not set)` / отсутствие данных остаётся `Не определено`, а не превращается в Direct;
- ручная корректировка источника имеет приоритет над автоматикой.

Data-driven attribution, MMM и сложные multi-touch модели пока не применяются: при малом объёме они создают больше шума, чем пользы.

## Канонические события

| Событие | Что означает | Создаёт CRM-лид |
|---|---|---|
| `whatsapp_click` | Клиент открыл WhatsApp с сайта | Да |
| `phone_click` | Клиент нажал номер телефона | Да |
| `calculator_complete` | Клиент получил расчёт Umzugsreinigung | Нет |
| `page_view` | Просмотр страницы | Нет |

Сервис (`umzugsreinigung`, `fensterreinigung`, `allgemeine_reinigung`) хранится как параметр события, а не как отдельное событие.

Старые `umzug_whatsapp_click`, `fenster_whatsapp_click` и `conversion_event_contact` могут оставаться в исторических данных для совместимости, но CRM их не считает отдельными лидами.

## First-party путь клиента

После согласия на аналитику браузер хранит локально:

- анонимный `journey_id`;
- first touch;
- last touch;
- last non-direct touch;
- до 12 значимых касаний в `touch_path`;
- UTM-параметры;
- GCLID / GBRAID / WBRAID, если Google их передал;
- первую и последнюю страницу входа.

До согласия исходный переход временно удерживается только в `history.state`, чтобы cookie-banner/reload не уничтожил рекламный контекст.

PII (имя, телефон, email) в GA4-параметры атрибуции не отправляется.

## Надёжность источника

Каждый лид получает `Основание атрибуции` и `Уверенность`.

| Основание | Уверенность по умолчанию |
|---|---|
| First-party путь сайта | Высокая для известного внешнего источника |
| ID рекламного клика | Высокая |
| GA4 session source/medium | Средняя–высокая |
| Referrer | Средняя |
| Direct | Средняя/низкая как доказательство маркетингового источника |
| Нет данных | Низкая |
| Ручная правка / со слов клиента | Высокая, если источник известен из разговора |

## CRM-поля атрибуции

Основные видимые поля остаются понятными:

- Источник
- Канал
- Кампания
- Ключевая фраза
- ID рекламного клика
- Страница входа

Технические поля после `AB`:

- Автоисточник
- Первый источник / канал
- Последний источник / канал
- Основание атрибуции
- Уверенность
- Тип трафика
- Путь клиента
- Первый / последний вход
- ID пути
- Автоканал

`Y:AB` зарезервированы для Google Ads offline conversion export и не должны смещаться.

## Google Ads

В Google Ads возвращаются только реальные CRM-этапы с доступным click ID:

- `Забронирован` → `Fleissig - Auftrag gebucht`
- `Выполнен` → `Fleissig - Auftrag abgeschlossen`

Ценность конверсии берётся из реальной суммы заказа/офера в CRM. Это позволяет постепенно обучать рекламу не на клики WhatsApp, а на фактически полученные заказы.

## Контроль качества

После изменений проверяем:

- нет ли двух CRM-лидов на один WhatsApp-клик;
- `Не определено` не превращается в Direct;
- рекламный переход с click ID определяется как Google Ads;
- первая страница и first-touch переживают cookie consent;
- источник можно вручную исправить, и синхронизация не перезапишет правку;
- статус/сумма заказа остаются ручными CRM-данными и не затираются;
- `Attribution` показывает first-touch и last-touch рядом;
- Google Ads Export включает только строки с рекламным click ID.

## Принцип принятия решений

Для бюджета смотрим в таком порядке:

1. реальные заказы и выручка в CRM;
2. источник с уровнем уверенности;
3. first-touch vs last-touch;
4. стоимость рекламы;
5. только затем — платформенные конверсии Google/Meta.

Никогда не суммируем конверсии разных рекламных платформ как разные заказы.
